Runtime

Sessions

Claude Code conversations for every account, plus open Desktop and browser windows. Click a session to read it, resume it in Terminal or continue it in Chat.

Claude Code status is worked out from its transcript files and running processes, so Needs approval? is a best guess. An open window only means the app is running — it doesn't show which account is signed in or whether Claude is busy.
Multi-window workspace

GUI Windows

Open Claude.ai and Claude Desktop for several accounts side by side. Each account opens with its own browser profile or Desktop data folder.

Claude.ai in separate browser profiles is the most reliable way to keep several accounts signed in at once. Claude Desktop copies each get their own data folder, but which account is signed in there can't be verified from outside the app — sign in to a new copy right after opening it, because the newest copy receives the sign-in link.

Claude Code, in the dashboard

Chat

Several Claude Code sessions side by side, each on any account. Type into a pane to send it a message; open existing conversations from Sessions or Tasks.

Each message runs claude -p --resume under the pane's account, so panes work in parallel and keep their history. Plan is read-only; Ask refuses tools that need approval (continue in Terminal for those); Edit may change files. Don't reply to a session that is also open in a Terminal — the two would branch apart.

Plan limits & tokens

Usage

5-hour and weekly plan limits come from each account's Claude Desktop accounting. Token counts come from Claude Code transcripts; dollar figures are what the same tokens would cost at API list prices — a way to compare accounts, not a bill.
